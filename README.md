# Deal Room Reconciliation

A reconciliation engine that cross-checks a billing system export against an ERP/ledger export and a signed-contract list, and flags exactly the discrepancies a diligence team finds in week one of a data room — before anyone opens the folder.

**[Live demo / output →](https://claude.ai/artifact/Kruh9mbHxKWr5mfCMpYQ3Y)**

## Why

Three failure modes show up over and over in pre-raise and pre-acquisition financial diligence: revenue booked in the wrong system, the wrong period, or at the wrong amount — and a company usually finds out the hard way, a few weeks before the data room goes live, when the numbers stop holding together. This automates the cross-check instead of relying on someone catching it by eye.

## What it catches

- **Revenue leakage** — invoiced in billing, never booked in the ERP
- **Phantom ERP entries** — booked in the ledger with no underlying invoice
- **Wrong-period booking** — revenue recognised outside the quarter it was earned in
- **Amount mismatches** — the two systems disagree on the same invoice
- **Currency conversion gaps** — a foreign-currency invoice and its EUR booking were never reconciled against each other
- **Likely duplicate payments** — the same bill paid twice under a near-identical supplier/customer name (fuzzy name matching, not just an exact-ID lookup)
- **Contract drift** — invoiced amount doesn't match the signed contract value, even when both internal systems agree with each other

## How it works

`generate_data.py` builds a synthetic dataset for a fictional company (60+ invoices across billing, ERP and contracts) with 8 deliberately planted discrepancies, one of each type above.

`reconcile.py` is the engine: matches transactions by ID across both systems, fuzzy-matches customer names to catch near-duplicates, checks posting period against issue date, and compares invoiced amounts against the signed contract list. Every flag comes with a plain-English reason and the raw evidence from both systems — no black-box scoring.

```
python3 generate_data.py   # builds the synthetic dataset
python3 reconcile.py       # runs the reconciliation, writes findings.json
```

Result on the included dataset: 62 transactions checked, 9 flags raised (8 distinct root causes — one caught independently by two different checks), EUR 56,280 in total exposure flagged. Full findings in `findings.json`.

## Data

All data in this repo is synthetic, generated by `generate_data.py`. No real company, customer, or transaction data was used.
